# Internationalization

[繁體中文](I18N.zh-Hant.md)

PureLink supports `en` and `zh-Hant`. Add a locale by extending `src/i18n.js`; page renderers and browser modules consume that one message source.

Locale selection is resolved in this order: the `purelink_locale` cookie, an explicit supported route prefix, `Accept-Language`, then English. `zh-TW`, `zh-Hant-TW`, `zh-HK`, and related Traditional Chinese variants resolve to `zh-Hant`; English variants resolve to `en`.

Indexable application and policy pages use `/en/...` and `/zh-Hant/...`. Root redirects to the selected locale. Existing shared content is intentionally never localized: `/slug` still opens content and `/slug+` still previews a URL destination. Only exact supported locale names are prefixes, and those names are reserved from new custom slugs.

The language switcher posts a preferred locale cookie without requiring an account. Localized indexable pages emit a canonical URL and `hreflang` links. Private, report, management, account, and shared-content pages remain noindex.

Manual browser QA: test fresh private windows with `zh-TW`, `en-US`, and an unsupported language; change language in both directions; reload after changing it; open `/slug` and `/slug+`; and check the switcher on a narrow mobile layout.
